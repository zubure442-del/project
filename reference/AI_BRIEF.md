# Брифинг для ассистента, который будет делать мобильное приложение

Это входной документ. Прочитай его целиком до того, как писать код.

## Что тебе передали

| Файл | Что внутри |
|---|---|
| `main.py` | Рабочий Python-скрипт: подключение к кольцу по BLE, выгрузка архивов, графики, расчёт индекса. Референс поведения, не образец архитектуры |
| `PROTOCOL.md` | Спецификация BLE-протокола кольца: команды, форматы пакетов, ловушки |
| `ALGORITHMS.md` | Все расчёты: фильтр артефактов пульса, агрегация сна, индекс Vuelo |
| `sample_packets.json` | Реальные ответы кольца и ожидаемый результат разбора — готовые фикстуры для тестов |

## Что это за устройство

Умное кольцо «Vuelo Ring», китайское, официальное приложение — `com.jaga.ibraceletplus.jyring`.
Протокол восстановлен декомпиляцией этого приложения и экспериментами. Официальной
документации нет, поэтому `PROTOCOL.md` — единственный источник истины; расхождения
между ним и `main.py` трактуй в пользу `PROTOCOL.md`.

## Что уже проверено на живом устройстве

- выгрузка шагов, сна, пульса, давления, стресса, глюкозы, HRV и офлайн-SpO2;
- автозамер: команда `0x19` включает и пульс, и офлайн-SpO2, ответ `0x19` = принято;
- SpO2 кольцо пишет по одному замеру на слот; пока `0x19` уходит при каждом подключении,
  замеры идут почти каждые 30 минут (21.09: 22 за полдня). Без кольца на руке их нет;
- сон кольцо отдаёт в дневных сессиях и не отдаёт ночью (до ~04:00), поэтому сон хранится в кэше;
- настройку автозамера надо переотправлять при каждом подключении, иначе кольцо
  со временем перестаёт писать SpO2. Это ключевой момент, см. `PROTOCOL.md`, раздел 4.

## Чего делать не нужно

- Переносить Python-код механически. Разбор пакетов и расчёты перепиши заново,
  сверяясь с двумя markdown-файлами.
- Тащить в приложение «пессимистичную» логику индекса как есть: она считает
  отсутствующие данные нулём. См. `ALGORITHMS.md`, раздел 3, последний абзац.
- Обещать медицинскую точность. Давление и глюкоза у таких колец — оценка по
  фотоплетизмограмме, а не измерение. В интерфейсе это должно быть видно.

## Рекомендуемый стек

React Native + Expo + TypeScript, `expo-router`, BLE через `react-native-ble-plx`.
Важно: `react-native-ble-plx` не работает в Expo Go и в симуляторе iOS — нужен
development build и настоящее устройство. Хранение — SQLite или MMKV,
состояние — Zustand, графики — Skia или Victory Native.

Слои: транспорт BLE → кодек пакетов (чистые функции, без побочных эффектов) →
хранилище → расчёты → интерфейс. Кодек и расчёты должны быть покрыты юнит-тестами
на фикстурах из `sample_packets.json` — это то место, где ошибка стоит дороже всего.

## Порядок работы

1. Кодек пакетов + тесты на фикстурах. Без устройства.
2. BLE-транспорт: сканирование, подключение, подписка на notify, очередь команд,
   переотправка `0x19` при каждом коннекте.
3. Хранилище и синхронизация архивов по дням.
4. Расчёты и экраны.

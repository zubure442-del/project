# Vuelo Ring — iPhone-приложение

Приложение к умному кольцу «Vuelo Ring». Владелец — не мобильный разработчик (опыт: Python-скрипт).
Объясняй просто, давай точные команды для терминала и говори, что нужно нажать или проверить руками.
Язык общения и интерфейса: русский.

## Источники истины (папка reference/)
- `PROTOCOL.md` — BLE-протокол, единственный источник по байтам. Непонятное или расходящееся с main.py — спросить владельца, не угадывать.
- `ALGORITHMS.md` — расчёты. `sample_packets.json` — реальные фикстуры. `AI_BRIEF.md` — вводная.
- `main.py` — рабочий референс, НОВЕЕ ALGORITHMS.md в трёх деталях (следовать коду):
  - пульс за минуту = МЕДИАНА валидных подзамеров (30–220), не среднее;
  - SpO2: если все валидные значения слота одинаковы — ОДИН замер;
  - график пульса: бледные точки + скользящая медиана ±45 мин, линия рвётся при разрыве > 90 мин.
- Код main.py не переносить механически. Считать отсутствующие данные нулём (как там) — нельзя.

## Стек и архитектура
- Только iPhone. Expo + React Native + TypeScript (strict), expo-router, react-native-ble-plx через development build (НЕ Expo Go, не симулятор iOS — BLE там не работает).
- Тесты: Vitest для чистых слоёв (codec, domain).
- Слои: `src/ble` (транспорт) → `src/codec` (чистые функции) → `src/domain` (расчёты) → `src/storage` → `src/ui`. Кодек и расчёты покрыты тестами.
- Не добавлять библиотеки без необходимости, не усложнять архитектуру заранее.

## Время
Кольцо хранит ЛОКАЛЬНОЕ время как unix-секунды. Метку из пакета разбирать как UTC и НЕ переводить в зону (читать через getUTC*). При установке времени (0x01) — наоборот: epoch + смещение зоны.

## BLE
- ПРОВЕРЕНО НА УСТРОЙСТВЕ 20.09.2026 (лог `сыройлог.pdf`, подробности в PROTOCOL.md разделы 8 и 9):
  - сон приходит в окне запроса ШАГОВ (0x10); на сам 0x11 — пустышка с меткой времени 1. Разбирать пакеты по коду в байте 0, а не по ожидаемому ответу;
  - 0x55: три одинаковые записи в пакете = один замер, берём одну точку по времени первой записи; пакеты раз в 30 мин. Если записи различаются — разные замеры с шагом 15 мин;
  - 0x0B: заряд запрашиваем в конце выгрузки; бывает и сам при подключении (лог c).
- Ноль для стресса, HRV, давления и глюкозы — «замера не было», а не значение: официальное приложение усредняет только значения больше нуля и показывает ноль как «--».
- Зоны стресса: 0–30, 31–60, 61–80, 81–100. Названия нейтральные: Низкий, Умеренный, Повышенный, Высокий.
- Каждая команда ровно 20 байт (код + параметры + нули). Notify `000033f4-…`, write `000033f3-…`, имя `Vuelo Ring`.
- При КАЖДОМ подключении: сначала 0x01 (время), потом 0x19 (автозамер), иначе кольцо перестаёт писать SpO2. Критично.
- Конец потока — по маркеру (раздел «Запуск и синхронизация»); первый пакет ждём до 12 с.

## Продукт
- «Итог» (крупно) + три составляющие: сон, активность, организм. Организм — средний за день по замерам кольца (раздел «Организм (v2)»). Итог растёт в течение дня по мере шагов. Утренний текст — про ночь, вечерний — про день. Названия не копируют Whoop, Oura, Garmin и т.п.
- ОТСУТСТВУЮЩИЕ ДАННЫЕ НЕ НОЛЬ. Нет данных = `null`. **Итог — только когда посчитаны все три** (сон, активность, организм); по одной или двум он не строится, веса не пересчитываются. День с итогом — «полный».
- Отчёт с рекомендациями: шаблонный (30–40 фраз, выбор по самой слабой составляющей) через интерфейс `ReportGenerator`; позже — YandexGPT через собственный сервер-посредник. LLM сейчас НЕ подключать.
- Данные и история (7 дней: сводки и выданные советы) — только на телефоне. Сервера и БД нет.
- Веса итога: сон 15 / активность 70 / организм 15 (решение владельца). «Организм» v2 — средний за день по замерам (см. раздел «Организм»); давление и глюкоза входят в него как оценки кольца и на экране помечены «оценка».
- Заряд (0x0B): запрос отправляем в конце выгрузки — иначе заряда не будет.
- Никаких медицинских утверждений: без диагнозов, «усталость пройдёт», обещаний результата. Глюкоза и давление помечены «оценка», выводов и похвалы по ним нет.
- Стиль UI: тёмный фон, один акцентный цвет (цветом выделяем только данные), крупные тонкие цифры, кольцевые индикаторы, минимум текста.
- На карточке одна мысль. Пояснений абзацами на экранах нет. На Сне, Активности и Организме один «i» в шапке вкладки: описание метрик простыми словами (`src/domain/tab-info.ts`), без формул и чисел, в конце «Не является медицинским прибором». На карточках «i» нет, на «Сегодня» — тоже. Заголовков капслоком нет, радиус карточек один, рамок нет.
- **Календарь вместо выбора на графиках.** В шапке каждой вкладки (кроме «Профиля») кнопка-календарь с датой («21 сен»); лист с полосой из 7 дней, точка под числом — у дня есть Итог (подписи-легенды нет). Выбранный день один на все вкладки (`selectedDay`), любой день недели выбирается, кнопка «Сегодня» в листе. Центральная вкладка подписана «Сегодня» или датой выбранного дня.
- Оговорка везде одна: «Не является медицинским прибором» — константа `NOT_MEDICAL_DEVICE` в `src/domain/texts.ts` (общий файл текстов). Используется в «i» вкладок, внизу экрана загрузки и в «О приложении».
- Общий дисклеймер живёт только в онбординге и в «О приложении». Меню разработчика (сырой лог и демо-режим) спрятано: пять нажатий на версию.

## Демо-режим
- Вход — только через существующее меню разработчика: «О приложении» → пять нажатий на версию → экран «Сырой лог» (`src/app/raw-log.tsx`). Там кнопка «Демо-режим»; после включения на её месте «Выключить демо-режим» — всё возвращается к реальным данным. Других способов входа, плашек и переключателей нет.
- **Генерируются только второстепенные показатели** (`src/demo/generate.ts`, параметры — `DEMO`): ряды того же вида, что хранятся после выгрузки кольца (`RawByDay`) — фазы сна по минутам, шаги по минутам, пульс, замеры 0x55 (давление, стресс, глюкоза, вариабельность), кислород; раз в 30 минут, 14 дней (неделя на экране + неделя истории для нормы, ориентиров и постоянства сна), сегодня — до текущей минуты. Сон, Активность, Организм и итог считает тот же `rebuildDays`, что и после выгрузки (`demoState` в `src/state/demo.ts`); напрямую оценки не подставляются. Профиль — настоящий.
- **Изоляция:** демо живёт только в памяти провайдера (зерно + момент построения), `state`/`latest` и всё, что пишет в хранилище, — настоящие. Демо-состояние помечено `demo: true`, `saveState` такое не пишет. Нормы шагов, советы и отметки выгрузки у демо свои (пустые). После перезапуска приложения демо выключено; «Очистить данные» его выключает.
- В демо к кольцу не ходим (синхронизация, pull-to-refresh и возврат из фона ничего не делают), в шапке статус «Демо-режим». Каждое включение — новое зерно, своя неделя.

## Кислород
Запрос `0x40` в выгрузке есть, кислород — один из пяти показателей замера «Организма». Карточка на «Организме» показывается, только если замеры были за последние 3 дня.

## Замеры
Период автозамера кольца — всегда 30 минут (байт 6 команды `0x19`), настройки в интерфейсе нет.
Если приложение открыто, кольцо подключено и последний замер старше `GAP_MIN` = 90 минут,
запускается **один** живой замер (`0x23`), не чаще раза в 30 минут. Не удался — молча ничего не пишем.
В фоне это невозможно, и обходить ограничение iOS не пытаемся.

Пакеты `0x14` (живой пульс от кольца) сохраняются как замеры пульса того же дня.

## Очистка данных
Кнопка в «Профиле»: удаляет кэш, историю, профиль и сырые логи, но оставляет привязку к кольцу (её убирает «Забыть кольцо»). После очистки приложение ведёт себя как при первом запуске.

## Запуск и синхронизация
- **Любая синхронизация — только через экран загрузки** (`src/ui/LoadingScreen.tsx`, оверлей поверх вкладок): вход, возврат из фона (AppState background → active), pull-to-refresh, «Повторить». Других путей к кольцу за данными нет; фоновой догрузки нет. Живой замер после загрузки и отправка профиля — не синхронизация.
- **Правило 10 минут** (`CACHE_FRESH_MS`): если последняя удачная синхронизация свежее — к кольцу не идём, на 2 с «Данные актуальны».
- **По ходу загрузки состояние не трогаем.** Прогресс живёт в `loadProgress` (вне React), вкладки не перерисовываются по пакетам. Данные применяются один раз в конце (`applySyncResult` в `src/state/sync-plan.ts`).
- **Конец потока — по маркеру:** 23:45 у `0x10` (в его окне это может быть пакет сна `0x11`), `0x55`, `0x40`; счётчик `aa` или `16 ff` у `0x16`. После маркера 0.1 с (`DAY_END_GRACE_MS`), после последней `aa` 0.3 с (`TAIL_MS`), между запросами 0.1 с. Запасной idle 5 с. Первый пакет ждём 12 с (`FIRST_PACKET_MS`), повтор — только после 12 с тишины; `06 02` («занято») — ждём, не повторяем. Неделя по логу c: 67 → ~32 с (+~4 с рукопожатие).
- **Полнота дня — по маркерам, а не по наличию данных.** День выгружен целиком, если все четыре потока закрыты признаком; пустой день с маркерами тоже. Для таких дней в удачной синхронизации пишется время `syncedAt[дата]`. В ночной сессии (до 04:00) не пишется ничего — ночью кольцо не отдаёт сон.
- **Финальный день:** `syncedAt[D] ≥ startOfDay(D+1) + FINAL_AFTER_HOURS` (12 ч, местное время) — к полудню следующего дня весь сон уже пришёл.
- **Какие дни запрашивать** (`planDays`): сегодня — всегда; остальные — если их нет в кэше или они не финальные (вчера до полудня — заново). Списком, не диапазоном. Перезаход после полудня — только сегодня, ~11 с по логу c плюс подключение.
- **Новый пользователь** (`newUserTodayOnly`): пока ни у одного дня не было всех трёх метрик (флаг `hadCompleteDay`, липкий, сбрасывает только «Очистить данные»), повторные загрузки берут у кольца только сегодня. Самая первая загрузка — неделя целиком. После первого полного дня — обычный `planDays`. Минус: вечерняя часть ночи до полуночи приходит в окне вчерашнего дня, у нового пользователя её не будет. В отладочный лог пишется строка «запрос дней: …; из кэша: …» и по строке на день с причиной конца каждого потока.
- **Сон приходит днём и не приходит ночью.** `0x11` не запрашиваем, сон — в окне `0x10`. Сохранённый сон пустым ответом не стирается, пришедший — обновляет.
- **Обрыв связи** не выбрасывается: `runSync` возвращает частичный результат и `error`. Частичное сохраняем, «Обновлено» не ставим, `syncFailed = true`.
- **Экран ошибки** — только если связь вообще не установилась (или показывать нечего). Три текста: «не найдено», «связь оборвалась», «отвечает слишком медленно».
- **«Обновлено ЧЧ:ММ» только после удачной синхронизации.** При неудаче — «Не удалось обновить · данные на 18:02».
- **Плашка «Не все данные загружены · Повторить»** — только если последняя синхронизация кончилась ошибкой связи. Упор в `HARD_CAP_MS` (120 с) — не ошибка: недогруженные дни не отмечены завершёнными и придут в следующий раз.
- **Одно рукопожатие на подключение** (0x01 → 0x19 → 0x02, порядок не менять), лёгкие запросы (`0x13`, `0x03`, `0x0B`) не чаще раза в 5 с (`LIGHT_REQUEST_MS`).
- **Самый первый запуск (онбординг, `src/ui/Onboarding.tsx`):** сначала только логотип и «Начать», потом одна форма со всеми обязательными полями — имя, пол, рост, вес, год рождения, цель; «Пропустить» нет, под именем «Имя хранится только на вашем телефоне. Мы не собираем данные.». Профиль пишется с ожиданием записи; Bluetooth и загрузка — только после «Готово». После «Очистить данные» — снова онбординг.

## Экран загрузки
- Два вида. **С карточками** — только при первом запуске или если предстоит загрузить от `SLIDES_MIN_DAYS` (3) дней (например, после «Очистить данные»): приветствие, рисунок, карточка с подсказками, справа кольцо-прогресс с V, статус и «Шаг N из 4». **Быстрый** — всё остальное: приветствие, логотип с дугой, статус. На pull-to-refresh заголовок «Обновляем данные». Внизу две строки 11 pt в одну строку.
- **Процент равномерный по времени** (`src/state/loading.ts`): считается по ожидаемым длительностям частей загрузки — подключение, четыре запроса на день, разовые запросы, запись. Ожидаемое — медиана трёх последних удачных загрузок (`requestDurations`), по умолчанию 9 с на день из четырёх запросов. Идущая часть засчитывается по времени, но не больше 95 % своей доли. Процент только растёт.
- **Слайды по проценту:** слайд k — пока процент в [25(k−1), 25k) %; по одному и не чаще раза в `SLIDE_MIN_MS` (3 с). «Шаг N из 4» — показанный слайд, в самом конце долгой загрузки «Почти готово». Уходим, когда 4-й слайд показан 3 с.
- **Статус настоящий:** «Подключаемся…» / «Загружаем данные · N %».
- Смена карточки и рисунка — затухание 200 мс, свайпа нет. Рисунок — одна картинка в одном контейнере 4:5 (`ART_ASPECT`), «cover» по центру, мягкий градиент внизу в том же контейнере. Файлы `assets/loading/step-1.png … step-4.png` заменяются файлами с теми же именами; подгружаются заранее, при ошибке файла — векторная замена.
- Заголовок карточки капслоком — по макету `reference/design/loading-mock.png` (исключение из правила «без капслока»).
- Карточки: 1 «Как правильно носить кольцо», 2 «Забираем данные», 3 «Три показателя дня» (рисунок — кольцо и три кольца; сон, активность, организм), 4 «Персональный совет» (рисунок — кольцо с AI-чипом; итог, совет по слабой стороне, всё на телефоне).

## Профиль
Вкладка «Профиль»: карточки «Имя» (вверху, с подписью «Имя хранится только на вашем телефоне. Мы не собираем данные.»), «Биометрия» (пол, рост, вес, год рождения), «Цель». Имя к биометрии не относится. Хранится только на телефоне, в сеть не уходит.
- Экран показывает профиль из общего состояния (локально — только текст поля, которое правят) и перечитывает его из хранилища при открытии. Имя первого запуска пишется с ожиданием записи до старта Bluetooth.
- Пустые поля биометрии и цели — красная рамка и красная подпись, над блоком «Для корректной работы заполните эти поля». Красная точка на иконке «Профиль» — только пока не заполнено хотя бы одно из пяти обязательных полей (пол, рост, вес, год рождения, цель); имя и заряд на неё не влияют. Точка, плашки и рамки — из одной проверки `profileAlerts`. Правка профиля — только изменённые поля поверх актуального состояния; верные числа сохраняются сразу при вводе; кольцу профиль уходит через 1.5 с после последней правки.
 Границы в `PROFILE_LIMITS`. Возраст из профиля идёт в формулу максимального пульса и в команду `0x02`, которая отправляется кольцу при сохранении профиля и при каждом подключении после `0x01` и `0x19`. Пока профиль не заполнен, `0x02` не шлём и «умолчания» не подставляем. Плашка на вкладках: нет биометрии — «Биометрия не настроена · Настроить», биометрия есть, а цели нет — «Цель не выбрана · Выбрать».

## Шумоподавление шагов
`applyStepNoise` (`src/domain/step-noise.ts`) — только к ДНЕВНОЙ СУММЕ: до 1 500 × 0.60; 1 501–5 000 × 0.72; 5 001–7 000 минус (1 400 + (шаги − 5 000) / 2 000 × 600); больше 7 000 минус 2 000; округление, не меньше 0. Везде, где итог дня: число шагов на «Активности», % к норме, оценка активности, точки недели, история нормы, дистанция. Почасовой график «День», «Самый активный час», эпизоды и калории — по сырым минутным шагам.

## Дистанция
На «Сегодня» карточка «Дистанция и калории»: шаги после шумоподавления × рост в м × `STRIDE_COEFFICIENT` (0.414); меньше 1 000 м — «850 м», иначе «3.2 км» (`src/domain/distance.ts`). На «Активности» — число шагов и полоска «% нормы».

## Норма шагов
Своя на каждый день (`src/domain/steps-norm.ts`), вместо фиксированных 10 000:
- история — 7 дней до сегодняшнего, только дни с шагами от 1 000; n — их число, среднее — по ним;
- база = n/7 × среднее × 1.1 + (1 − n/7) × 10 000 (n = 0 → 10 000); сон: × (0.85 + 0.3 × оценка сна / 100), без оценки × 1;
- норма = база × сон, до сотен, от 5 000 до 15 000. Считается раз в день и хранится (`stepNorms`); посчитанная без сна пересчитывается один раз, когда сон появится. Для прошлых дней — сохранённая, иначе по данным до того дня;
- история и сравнение с нормой — по шагам после шумоподавления; от нормы считается шаговая часть оценки активности.

## Калории
Активные (без базового обмена), считаем сами для каждого дня по минутам (`src/domain/calories.ts`), одним методом, включая сегодня:
- по шагам: шаги минуты × `0.75 × вес × (0.415 × рост в м) / 1000`;
- по пульсу: между замерами линейно, если разрыв ≤ 20 мин; если пульс ≥ max(100, 0.5 × максимальный пульс) — Keytel (2005) минус BMR/1440 (Mifflin–St Jeor);
- в минуту — большее из двух, сумма за день округляется. Нет пола, роста, веса или года рождения — «—», умолчаний нет. Сводки пересобираются при правке профиля.
- Число кольца из `0x03` на экране не показываем — только строкой в отладочном логе для сверки.
- Где: «Дистанция и калории» на «Сегодня», строка под кольцом «Активности» (за выбранный день), карточка «Калории · неделя» на «Активности» (сумма за 7 дней и тонкие столбики; дни без данных не учитываются).

## Дни и оценки
- При каждом входе (запуск и возврат из фона) открывается сегодняшняя дата, в том числе ночью; выбор из календаря сбрасывается. «Сегодня» сверяется с часами телефона раз в минуту (`CLOCK_CHECK_MS`). `DAY_START_HOUR` (04:00) влияет только на ночные сессии синхронизации.
- День «с данными» — если в кэше есть хоть один тип: шаги, сон, пульс, сводка или кислород.
- Оценка считается для каждого дня по данным того дня.
- **Экран калибровки вместо переброса на вчера.** По умолчанию выбран сегодняшний день. Если у выбранного дня нет всех трёх метрик, «Сегодня» показывает только песочные часы (вместо логотипа), заголовок «Считаем вашу активность» и «Чтобы показатели за сегодня были точными, нам нужно больше данных. Дайте кольцу привыкнуть — осталось буквально несколько часов!» (для прошлого дня — знак «i» из набора `TipGlyph` вместо песочных часов, без заголовка, текст «За этот день данных недостаточно.») — без частичных метрик и шагов. Сон, Активность, Организм для такого дня приглушены и не открываются (вибрация «нет»), открытая вкладка переключается на «Сегодня». Календарь работает всегда; точка в нём — у дней с Итогом.
- **Плашки: видна одна**, по приоритету: ошибка синхронизации → «Биометрия не настроена» → «Цель не выбрана» (`bannerKind`).
- **Совет — только для полного дня.** В историю пишется совет последнего полного дня. На экране совет (как и все карточки-рекомендации) показывается только за сегодня.
- Недельный график показывает дни от первого с данными до последнего с данными; хвостовые пустые дни не рисуются.

## Кэш
Храним `CACHE_DAYS` = 30 дней, лишнее удаляется при запуске. Храним ПОЛНЫЕ ряды за каждый день и тип данных (`src/storage/raw.ts`), а не только итоговые числа: сводки пересчитываются из рядов. Частичная синхронизация обновляет ряды по дню и типу и только если по нему что-то пришло — пустое не затирает. Хранятся последние 7 дней. Ночь через полночь целиком относится ко дню пробуждения (вечерние минуты отрицательные).

## Эпизоды нагрузки
Минуты, где шагов не меньше `STEP_MIN_PER_MIN`, плюс интервалы, где пульс выше
`max(ACTIVE_HR_LOW_RATIO × максимальный пульс, пульс покоя + ACTIVE_HR_OVER_RESTING)`.
Соседнее склеивается при паузе до `MERGE_GAP_MIN`, эпизод короче `MIN_EPISODE_MIN` отбрасывается.
Шаги — основной признак: кольцо мерит пульс раз в 30 минут и прогулку может не заметить.

Квадратики на графике «День» (`loadBoxes`): по ширине — от начала до конца эпизода (не меньше 6 pt); центр — на линии пульса в середине эпизода (интерполяция по той же линии, что нарисована); высота `14 pt + шаги / максимум шагов × (0.8 × высота области − 14)`; общий коэффициент `s = min(1, min(2 × расстояние центра до края / h))` сохраняет пропорции и держит всё в области графика, не ниже 10 pt.

## Сон (модель)
`sleepScore` (`src/domain/score.ts`): clamp(0.45 × длительность + 0.25 × глубина + 0.20 × пробуждение + бонус, 0, 100).
- длительность — минуты сна к 420; глубина — доля глубокого в коридоре 15–25 % = 100, дальше штраф;
- пробуждение: ранность = clamp(100 × (660 − W) / (660 − 300)), W — минута подъёма; постоянство = clamp(100 − стандартное отклонение подъёма × 100/90) при 3+ прошлых ночах за 7 дней (разброс — по прошлым ночам и сегодняшней); компонент = 0.6 × ранность + 0.4 × постоянство, без постоянства — ранность;
- бонус = вчерашняя оценка активности / 100 × 10; нет — 0. Дни считаются по порядку дат.

## Организм (v2)
`src/domain/organism.ts`. Замер — запись 0x55 + ближайший кислород (±15 мин) + минимальный пульс за день к этому моменту; нужны 2 из 5 показателей (вариабельность, пульс, кислород, давление, глюкоза).
- подоценки: вариабельность clamp(50 + (x − ориентир) / ориентир × 200), пульс clamp(50 + (ориентир − x) / ориентир × 300); кислород, давление, глюкоза — прежние пороги из ALGORITHMS.md;
- личный ориентир — среднее за 7 прошлых дней с данными (минимум 5, иначе 50 мс и 65 уд/мин);
- оценка замера — веса 0.30 / 0.25 / 0.20 / 0.15 / 0.10, нормированные по имеющимся показателям;
- оценка дня — среднее замеров, взвешенное по покрытию (до следующего замера, не больше 30 мин; последний — до конца дня или до «сейчас»); покрытие меньше 4 ч — оценки нет.

## Карусель «AI Ассистент» и «Кофейное окно»

- «Кофейное окно» (`src/domain/coffee.ts`) — по факту наличия метрики «Сон» за сегодня: посчитана — карточка с таймлайном при любом значении (низком, среднем, высоком); не посчитана — карточки нет вовсе, без заглушек и без подстановки прошлой ночи (`coffeeInput` → null).
  - START = подъём сегодняшней ночи + 90 мин; CUTOFF = обычный отход ко сну (среднее за 7 ночей, иначе 22:00) − 8 ч. Таймлайн красный–зелёный–красный; START ≥ CUTOFF — «Сегодня лучше без кофе», полоса целиком красная, совета по чашкам нет. Над таймлайном: до окна — «Окно откроется в ЧЧ:ММ», в окне — «Окно открыто до ЧЧ:ММ», после окна и ночью (до 5:00) — «Сейчас не время для кофе…».
  - Под таймлайном — «На основе вашего сна рекомендуем не более N чашки/чашек сегодня, чтобы восстановить силы и не нарушить засыпание вечером.»; N по оценке сна за сегодня: < 60 → 1, 60–89 → 2, ≥ 90 → 3 (`COFFEE_CUPS_TWO_FROM`, `COFFEE_CUPS_THREE_FROM`). Прежнего предупреждения «сон был коротким» с волной ночи больше нет. В текстах только «кофе».
- **Карточки-рекомендации — только для сегодняшнего дня** (`recommendationsFor` в `src/state/day.ts`). На любом прошлом дне, выбранном в календаре, вся карусель «AI Ассистент» скрыта целиком: совет (Powered by YandexGPT), «Кофейное окно», «Цикл питания», «Пик выносливости», «Режим сна».

# Vuelo Ring — алгоритмы обработки данных

Всё, что скрипт считает поверх сырых пакетов. Перенос на другой язык — по этому файлу,
не по коду: код местами исторический.

---

## 1. Фильтр артефактов пульса

Кольцо иногда выдаёт замер, оторванный от соседних на 40–60 ударов: рука сдвинулась,
кольцо провернулось. Такой выброс ломает и график, и расчёт нагрузки.

Замер считается артефактом, если выполнено всё сразу:

- он отличается от последнего «хорошего» замера на `HR_GLITCH_JUMP` = 30 уд/мин и больше;
- следующий за серией замер возвращается к прежнему уровню в пределах
  `HR_GLITCH_RETURN` = 15 уд/мин;
- длина серии — не больше `HR_GLITCH_MAX_RUN` = 2 замеров подряд;
- разрыв по времени внутри проверяемого куска не превышает
  `HR_GLITCH_MAX_GAP` = 2400 с (40 минут).

Последний порог зависит от периода автозамера: при 15–30 минутах хватает 40 минут,
при периоде 60 минут его надо поднять примерно до 4200 с. Разумнее считать его
динамически: медиана интервалов между замерами × 1.5.

Сырой архив пульса не изменяется. Очищенные данные идут в график и в расчёт индекса,
число отфильтрованных замеров показывается пользователю.

## 2. Сон

Минутные состояния из `0x11` собираются в «сессии»: разрыв больше 2 часов начинает
новую сессию. Сессия относится к дате своей **последней** минуты — иначе ночной сон
разрезается полуночью пополам.

Внутри сессии: `состояние >= 80` — глубокий сон, `1..79` — лёгкий, `0` — бодрствование.

## 3. Индекс Vuelo (0–100)

Модель намеренно пессимистичная: она не «успокаивает», а штрафует. Три блока.

**Ресурс (вес 15 %)**

```
объём сна      = min(100, минут_сна / 420 * 100)
качество сна   = 100, если доля глубокого сна в 0.15..0.25
                 иначе max(0, 100 - |0.20 - доля| * 400)
база сна       = объём * 0.7 + качество * 0.3
оценка SpO2    = 100 при среднем >= 95 %, иначе max(0, 100 - (95 - среднее) * 20)
оценка HRV     = min(100, среднее / 65 * 100)
ресурс         = база сна * 0.6 + HRV * 0.2 + SpO2 * 0.2
```

**Активность (вес 70 %)**

```
шаги           = min(100, шаги_за_день / 10000 * 100)
максимальный пульс = 208 - 0.7 * возраст
кардио         = за каждый очищенный замер пульса: >85 % максимума +2.0,
                 70..85 % +1.0, 60..70 % +0.5
нагрузка       = min(100, шаги * 0.7 + кардио * 4)
```

**Метаболизм (вес 15 %)**

```
глюкоза        = 100 при <= 5.2 ммоль/л, иначе max(0, 100 - (глюкоза - 5.2) * 40)
давление       = 100 при < 120/80; 70 при <= 130/85; иначе max(0, 100 - (сист - 130) * 5)
метаболизм     = глюкоза * 0.5 + давление * 0.5
```

**Сборка и штрафы**

```
индекс = ресурс * 0.15 + нагрузка * 0.70 + метаболизм * 0.15
штраф  = 1.0
         - (глюкоза - 6.0) * 0.4, если средняя глюкоза > 6.0
         - 0.2, если сон есть, но меньше 4 часов
индекс = max(0, индекс * штраф)
```

**Известная особенность.** Отсутствующие данные считаются нулём, а не «нет данных».
День без замеров SpO2 занижает индекс так же, как реальная гипоксия. То же с HRV,
глюкозой и давлением — при их отсутствии метаболический блок даёт ровно 0 из 15.
Это осознанный выбор автора для личного скрипта, но для приложения на нескольких
пользователей так нельзя: нужно либо перевзвешивать доступные компоненты, либо
показывать «недостаточно данных». Решение за владельцем продукта.

## 4. Единицы и интервалы

| Величина | Источник | Шаг по времени |
|---|---|---|
| Шаги | `0x10` | 1 мин |
| Сон | `0x11` — но приходит в окне запроса `0x10`, см. PROTOCOL.md раздел 8 | 1 мин (15 одинаковых байт = 15 минут одной фазы) |
| Пульс | `0x16` | 1 мин (две минуты в пакете) |
| Давление, стресс, глюкоза, HRV | `0x55` | один замер на пакет, пакеты раз в 30 мин (период автозамера) |
| SpO2 | `0x40` | один замер на 15-минутный слот; при `0x19` на каждом подключении — почти каждые 30 мин |
| Заряд | `0x0B` | в ответ на запрос (запрашиваем в конце выгрузки); бывает и сам при подключении |

Глюкоза передаётся умноженной на 10.

## 4a. Оценка «организма»

Заменена моделью v2 — см. раздел 14: средний «Организм» за день по замерам с личным ориентиром.

## 5. Ноль — это не замер

Для стресса, HRV, давления и глюкозы значение `0` означает «замера не было», а не «ноль».
Официальное приложение усредняет только значения больше нуля, а ноль показывает как «--».
На живом кольце нули приходят лишь в служебном пакете `23:45`, где вся запись нулевая.
То же правило у SpO2: `0` и `255` — не данные.

## 6. Зоны стресса

Как в официальном приложении, четыре зоны: `0–30`, `31–60`, `61–80`, `81–100`.
Названия в интерфейсе нейтральные — «Низкий», «Умеренный», «Повышенный», «Высокий»:
это оценка кольца по пульсовой волне, а не медицинский показатель.

## 7. Итог дня (приложение)

Итог = сон × 15 % + активность × 70 % + организм × 15 % — **только когда посчитаны все три**.
По одной или двум составляющим итог не строится, веса не пересчитываются: «70 % активности»
без сна и организма выглядел бы как оценка дня. День с итогом называется **полным**.
Если у выбранного дня нет всех трёх метрик, «Сегодня» показывает экран калибровки (раздел 11), а совет
даётся только по полному дню. Это заменяет «пессимистичную» логику из раздела 3: отсутствующее — не ноль.

## 8. Норма шагов (приложение)

Вместо фиксированных 10 000 — своя норма на каждый день (`src/domain/steps-norm.ts`).

```
история  = шаги за 7 дней до сегодняшнего (сегодня не входит), только дни с шагами >= 1 000
n        = число таких дней, среднее — по ним
база     = n/7 × среднее × 1.10 + (1 − n/7) × 10 000        (n = 0 → 10 000)
сон      = 0.85 + 0.30 × оценка сна за день / 100            (нет оценки → 1)
норма    = clamp(round(база × сон, до сотен), 5 000, 15 000)
шаги в оценке активности = min(100, шаги / норма × 100)
```

Норма считается один раз в день — как только есть оценка сна, либо при первом расчёте дня без сна
(тогда один раз пересчитывается, когда сон появится) — и хранится. Для прошлого дня без сохранённой
нормы — по данным до того дня. Примеры: новичок — 10 000; сон 90 — 11 200; сон 20 — 9 100.
Шаги в истории и в сравнении с нормой — после шумоподавления (раздел 12).

## 9. Какие дни запрашивать (приложение)

Сегодня — всегда. Остальные дни недели — если их нет в кэше или они не финальные.
День D финальный, если последний раз выгружен целиком (все потоки закрыты маркером) не раньше
startOfDay(D+1) + 12 ч по местному времени. Ночью (до 04:00) время выгрузки не пишется: кольцо тогда не отдаёт сон.
Экран загрузки с карточками — только если запрашивается от 3 дней; иначе быстрый экран.

**Новый пользователь.** Пока ни у одного дня не было всех трёх метрик (флаг `hadCompleteDay`), повторные
загрузки берут у кольца только сегодняшний день. Первая загрузка — неделя целиком; после первого полного дня — правило выше.

**Слияние с кэшем.** Пришедшие ряды ложатся на сохранённые объединением по минутам: минута из ответа заменяет
ту же минуту, остальные остаются. Пустой или оборванный ответ ничего не стирает.

## 10. Активные калории (приложение)

Считаем сами для каждого дня по минутам (`src/domain/calories.ts`), одним методом для всех дней.
Нужны пол, рост, вес и год рождения (возраст = текущий год − год рождения); нет хотя бы одного — «—».

```
ккал_на_шаг   = 0.75 × вес_кг × (0.415 × рост_м) / 1000
ккал_шаги(m)  = шаги в минуту m × ккал_на_шаг            (шаги — из пакетов 0x10, 255 = нет данных)
пульс(m)      = линейно между соседними замерами, если разрыв <= 20 мин; иначе пульса нет
порог         = max(100, 0.5 × (208 − 0.7 × возраст))
Keytel (ккал/мин): муж (−55.0969 + 0.6309·HR + 0.1988·вес + 0.2017·возраст) / 4.184
                   жен (−20.4022 + 0.4472·HR − 0.1263·вес + 0.074·возраст) / 4.184
BMR (Mifflin–St Jeor): 10·вес + 6.25·рост_см − 5·возраст + 5 (муж) / − 161 (жен)
ккал_пульс(m) = max(0, Keytel − BMR / 1440), только если пульс(m) >= порог
ккал(m)       = max(ккал_шаги(m), ккал_пульс(m))             — большее, не сумма
день          = round(Σ ккал(m))
```

Контроль: BMR мужчины 30 лет, 175 см, 70 кг — 1 648,75; женщины 30 лет, 165 см, 60 кг — 1 320,25.
Число кольца из `0x03` на экране не показываем, только в отладочном логе для сверки.
Неделя: сумма за 7 последних дней, дни без значения не учитываются.

## 11. Когда у дня нет всех трёх метрик

Если у выбранного дня нет всех трёх метрик, «Сегодня» показывает экран калибровки: логотип,
«Считаем вашу активность» и «Чтобы показатели за сегодня были точными, нам нужно больше данных.
Дайте кольцу привыкнуть — осталось буквально несколько часов!» (для прошлого дня — «За этот день
данных недостаточно.»). При входе всегда открывается сегодняшняя дата. Частичные метрики не
показываются; Сон, Активность и Организм для такого дня не открываются. Переброса на вчера нет.

## 12. Шумоподавление шагов (приложение)

Только к дневной сумме (`src/domain/step-noise.ts`), округление до целого, не меньше 0:

```
0–1 500        шаги × 0.60
1 501–5 000    шаги × 0.72
5 001–7 000    шаги − (1 400 + (шаги − 5 000) / 2 000 × 600)
больше 7 000   шаги − 2 000
```

Дистанция на «Сегодня»: шаги после шумоподавления × рост в метрах × 0.414; меньше 1 000 м — «850 м», иначе «3.2 км».
Почасовой график дня, эпизоды нагрузки и калории — по сырым минутным шагам.

## 13. Сон (приложение, новая модель)

```
длительность  = min(100, минут_сна / 420 × 100)
глубина       = 100 при доле глубокого 0.15..0.25, иначе max(0, 100 − |0.20 − доля| × 400)
ранность      = clamp(100 × (660 − W) / (660 − 300), 0, 100)        W — минута подъёма
постоянство   = clamp(100 − σ_подъёма × 100/90, 0, 100)             при 3+ прошлых ночах за 7 дней
пробуждение   = 0.6 × ранность + 0.4 × постоянство  (нет постоянства → ранность)
бонус         = вчерашняя активность / 100 × 10                     (нет → 0)
базовая_оценка = clamp(0.45 × длительность + 0.25 × глубина + 0.20 × пробуждение + бонус, 0, 100)
сон           = min(100, базовая_оценка × коэффициент_ночного_пульса)   коэффициент — раздел 20
```

## 14. Организм v2 (приложение)

Замер — запись `0x55` + ближайший кислород (±15 мин) + минимальный пульс за день к этому моменту;
нужны хотя бы 2 показателя из 5.

```
ориентир       = среднее за 7 прошлых дней с данными (минимум 5 дней), иначе ВСР 50 мс, пульс 65
ВСР            = clamp(50 + (x − ориентир) / ориентир × 200, 0, 100)
пульс          = clamp(50 + (ориентир − x) / ориентир × 300, 0, 100)
кислород       = 100 при >= 95 %, иначе max(0, 100 − (95 − x) × 20)
давление       = 100 при < 120/80; 70 при <= 130/85; иначе max(0, 100 − (сист − 130) × 5)
глюкоза        = 100 при <= 5.2, иначе max(0, 100 − (x − 5.2) × 40)
замер          = Σ вес × подоценка / Σ вес (веса 0.30 / 0.25 / 0.20 / 0.15 / 0.10 по имеющимся)
день           = Σ замер × покрытие / Σ покрытие; покрытие — до следующего замера, не больше 30 мин
                 (последний — до конца дня или до «сейчас»); меньше 4 ч покрытия — оценки нет
```

## 15. Кофейное окно (приложение)

Только для текущего дня и только когда оценка сна за сегодня посчитана — при любом её значении.
Оценки сна за сегодня нет — карточки нет вовсе (прошлая ночь не подставляется).

```
START   = подъём сегодняшней ночи + 90 мин
CUTOFF  = среднее время отхода ко сну за 7 ночей (нет — 22:00) − 8 ч
START >= CUTOFF              → «Сегодня лучше без кофе» (таймлайн целиком красный, чашек нет)
до START (после 5:00)        → «Окно откроется в ЧЧ:ММ»
START..CUTOFF                → «Окно открыто до ЧЧ:ММ»
после CUTOFF или до 5:00     → «Сейчас не время для кофе. Следующее окно — после следующего пробуждения.»
```

Под таймлайном — число чашек N по оценке сна за сегодня (0–100). **Только для текущего дня.**

| Оценка сна | N | Текст |
|---|---|---|
| < 60 (`COFFEE_CUPS_TWO_FROM`) | 1 | На основе вашего сна рекомендуем не более 1 чашки сегодня, чтобы восстановить силы и не нарушить засыпание вечером. |
| 60–89 | 2 | На основе вашего сна рекомендуем не более 2 чашек сегодня, чтобы восстановить силы и не нарушить засыпание вечером. |
| 90–100 (`COFFEE_CUPS_THREE_FROM`) | 3 | На основе вашего сна рекомендуем не более 3 чашек сегодня, чтобы восстановить силы и не нарушить засыпание вечером. |

**Время показа совета по чашкам:** только с 6:00 до 18:00 по часам телефона
(`COFFEE_ADVICE_FROM_MIN` = 360, `COFFEE_ADVICE_UNTIL_MIN` = 1080, интервал [6:00, 18:00)).
Вне этого окна карточка показывает статус и таймлайн, а совета по чашкам нет — и другого текста на его месте тоже.

```
6:00 ≤ сейчас < 18:00  → статус + таймлайн + «…не более N чашек…»
иначе                  → статус + таймлайн
```

Оценка сна — та же, что на экране (округлённая). Прежнее правило «при коротком сне — предупреждение
вместо окна» отменено. На прошлых днях все карточки-рекомендации (кофейное окно, совет, «Скоро») скрыты.

## 16. Демо-режим (приложение)

Генерируются **только второстепенные показатели** — входы расчёта, а не Сон, Активность, Организм
или итог. Формат — тот же, что у рядов после выгрузки кольца (`RawByDay`, `src/demo/generate.ts`):

```
сон        — фаза на каждую минуту ночи блоками по 15 мин (0 бодрствование, 15–60 лёгкий, 82–99 глубокий);
             ночь 6.5–8.2 ч, глубокого 15–24 %; каждая пятая ночь короткая: 4.2–5.5 ч, глубокого 7–12 %
шаги       — по минутам: прогулки 95–115 шаг/мин + мелкие движения; 5 000–13 000 за день до шумоподавления
пульс      — раз в 30 мин: сон 50–58, покой 66–78, ходьба +14–24; 30 % дней — вечерняя тренировка 128–148
0x55       — раз в 30 мин: давление 108–126 / 68–81, стресс, глюкоза 4.7–5.3 (+0.3 после еды), ВСР 52–72 ночью / 34–50 днём
кислород   — раз в 30 мин: 95–99 днём, 94–98 ночью
```

Период — 14 дней до сегодняшнего включительно, сегодня — до текущей минуты. Дальше ряды идут через
те же функции, что и данные кольца (`rebuildDays` → `buildSnapshots`: разделы 1, 8, 10, 12–14 и 7).
Демо-состояние только в памяти и в хранилище не пишется.

## 17. Эстафета / орехи / серия (приложение)

Код — `src/domain/relay.ts`. Шаги дня — после шумоподавления (раздел 12), норма — норма шагов дня (раздел 8).

```
выполнен(D)   = шаги(D) ≥ норма(D)                       (нет шагов — не выполнен)
осталось      = max(0, норма(сегодня) − шаги(сегодня))   (0 → «Зелёный свет»)
```

Начисление — по кэшу при открытии приложения и после выгрузки, только за прошедшие дни (D < сегодня),
которые позже последнего засчитанного и ещё не помечены «начислено». Дни — по порядку дат:

```
для каждого такого D с выполненной нормой:
  если D = последний_засчитанный + 1 день → серия = серия + 1
  иначе                                  → серия = 1, выплаченные ступени = ∅
  орехи += 5                                                (RELAY_DAY_REWARD)
  если серия = ступень лестницы и она не выплачена → орехи += бонус ступени
  пометить D «начислено», последний_засчитанный = D
огонёк на экране = серия, если последний_засчитанный = вчера; иначе 0
```

Лестница `STREAK_LADDER` (не кумулятивно: каждая ступень — своя сумма, один раз за серию):

| Дней подряд | Орехов |
|---|---|
| 7 | 50 |
| 30 | 500 |
| 60 | 2 000 |
| 120 | 5 000 |
| 365 | 30 000 |

Пример: 30 дней подряд = 30 × 5 + 50 + 500 = 700 орехов; на 30-й день начисляется 5 + 500.
Пропуск обнуляет серию и лестницу: следующие 7 дней подряд снова дают 50.
Невыполненный день не записывается: если полные шаги прошедшего дня придут позже, он засчитается и серия продолжится.

## 18. Динамика за неделю (приложение)

Код — `src/domain/trend.ts`. Заменяет прежние недельные графики на «Сегодня», «Сне», «Активности» и «Организме».

```
окно «эта неделя»    = 7 завершённых дней до выбранного дня (сам день НЕ входит: он ещё идёт)
окно «прошлая»       = 7 дней до них
среднее окна         = по дням, где показатель посчитан (пустые дни не занижают среднее)
процент              = round((среднее_этой − среднее_прошлой) / среднее_прошлой × 100)
```

Если в каком-то окне меньше `TREND_MIN_DAYS` = 3 дней с данными, работает запасной способ —
свежий день против личной нормы недели:

```
свежий день  = последний день с данными в [asOf − 6 … asOf] (сегодняшний тоже подходит)
норма        = среднее по ОСТАЛЬНЫМ дням с данными в том же окне
процент      = round((свежий − норма) / норма × 100)
```

Сравнение с одним старым днём давало дикие проценты («+3300 %»), поэтому база — среднее.
Дополнительно: база меньше `TREND_MIN_BASE` = 20 — процента нет вовсе; |процент| больше
`TREND_MAX_PERCENT` = 200 — на экране «более 200 %».
Меньше двух дней с данными — процента нет, на экране остаётся заголовок карточки.
Окно — `TREND_WINDOW_DAYS` = 7; в кэше держим `SNAPSHOT_DAYS` = 14 дней сводок.

## 20. Пульс во сне (приложение)

Код — `src/domain/sleep-hr.ts`, сборка дня — `src/storage/build.ts`. Возрастные границы больше
не используются: сравнение строго со своей нормой.

```
за ночь                  =  min и среднее замеров пульса внутри сессии сна (нужно ≥ 3 замера)
своя норма (7 дней)      =  среднее min и среднее средних по ночам СЕМИ ПРЕДЫДУЩИХ дней кэша,
                            нужно не меньше 5 таких ночей, иначе нормы нет
Δmin = min_ночи − норма_min          Δavg = среднее_ночи − норма_avg      (целые уд/мин)
```

Окно 7 дней и минимум 5 дней — тот же принцип, что у личного ориентира «Организма» (раздел 14).

Категории (проверяются в этом порядке, `NORMAL_RANGE` = 3, `SIGNIFICANT_THRESHOLD` = 4):

```
1  Всё в норме                     |Δmin| ≤ 3  И  |Δavg| ≤ 3                       ×1.00
2  Повышенная нагрузка             Δmin ≥ +4   И  Δavg ≥ +4                         ×0.75
3  Режим глубокого расслабления    Δmin ≤ −4   И  (Δavg ≤ −4 ИЛИ |Δavg| ≤ 3)        ×1.25
4  Неравномерный ночной ритм       Δmin ≤ −4   И  Δavg ≥ +4                         ×0.50
5  Резкое ускорение под утро       Δmin ≥ +4   И  (Δavg ≤ −4 ИЛИ |Δavg| ≤ 3)        ×1.00
–  Смешанная картина (запасная)    ни одно условие не подошло                       ×1.00
```

Запасная категория нужна для пограничных случаев (например, Δmin = 0 при Δavg = +5): вывода
не делаем и оценку сна не трогаем.

```
оценка «Сон» = min(100, базовая_оценка × коэффициент)      нормы ещё нет → коэффициент 1
```

На экране: «Минимальный 47 (-2 от вашей нормы)», «Средний 59 (+5 от вашей нормы)», ниже — текст
категории с цветной точкой: зелёная у «Всё в норме» и «Глубокого расслабления», красная у остальных,
серая — пока нормы нет. Названия категории на экране нет. Нормы ещё нет — только числа и «Наберётся несколько ночей —
сравним с вашей нормой». Диагнозов приложение не ставит.

## 21. Цикл питания (приложение)

Код — `src/domain/food.ts`, данные — `src/state/food.ts`. Карточка живёт в карусели
«AI Ассистент» перед «Кофейным окном» и видна только за сегодняшний день.

```
ночная глюкоза дня  =  замеры 0x55 внутри отрезков сна (часть ночи после полуночи),
                       рядом с которыми (± 5 минут) нет активных минут (шаги ≥ 20/мин)
личная норма        =  МЕДИАНА ночных замеров за последние 7 дней (нужно ≥ 3 замера)
коридор нормы       =  от −10 % до +25 % личной нормы (границы включительно)
сегодняшняя глюкоза =  медиана ночных замеров сегодняшней ночи
```

Медиана, а не среднее: один выброс не сдвигает норму. Режим (проверки строго по порядку):

```
1  глюкоза > +25 %  И  индекс «Сон» > 70   →  Подозрение на гипергликемию
2  индекс «Сон» ≤ 70  ИЛИ глюкоза < −10 %  →  Режим восстановления
3  иначе                                   →  Базовый режим
```

Глюкозы нет вовсе — режим решает один сон (пункты 2 и 3). Расписание от пробуждения
(для диапазонов берётся середина — на экране одно время):

```
Базовый           первый = подъём + 5 ч,  второй = первый + 5.5 ч
Восстановление    завтрак = подъём + 1.25 ч (1–1.5),  обед = +6.5 ч (6–7),  ужин = +11.5 ч (11–12)
Гипергликемия     первый = подъём + 5 ч,  второй = подъём + 10 ч
```

Голодание и аутофагия:

```
точка отсчёта  =  минута с минимальной глюкозой в последние 4 часа ПЕРЕД засыпанием
                  (вечер накануне — отрицательные минуты); замеров нет → минута засыпания
конец паузы    =  «сейчас», а если первый приём уже прошёл — время первого приёма
аутофагия      =  max(0, конец_паузы − точка_отсчёта − 12 ч)
```

Формат: крупно «3 часа 40 минут» (при нуле — «0 часов»), под ним мелко «аутофагии за ночь».
Таймлайн начинается за 90 минут до первого приёма пищи: начало не подписано, а зелёным выделена
пауза до первого приёма. Точки — приёмы пищи, над ними мелко название и время. Отметки «сейчас»
на этом таймлайне нет. Рядом со счётчиком — кнопка «i» с постоянным текстом про аутофагию
(`AUTOPHAGY_INFO`), без медицинских утверждений.

## 23. Оценка недели по активным калориям (приложение)

Код — `src/domain/calories.ts` (`weekActivityLevel`), показывается на карточке «Расход активных
калорий за неделю».

```
BMR (Mifflin–St Jeor)   мужчины: 10×вес + 6.25×рост − 5×возраст + 5
                        женщины: 10×вес + 6.25×рост − 5×возраст − 161
коридор активных ккал   похудение 30–45 % BMR;  поддержание 20–35 %;  набор массы 15–25 %
средний расход за день  по ЗАВЕРШЁННЫМ дням недели (сегодняшний ещё идёт и среднее занижает)
меньше коридора         «Низкая активность» (красным)
в коридоре              «Идеальная активность» (зелёным)
больше коридора         «Высокая активность» (красным)
```

Перебор при верно выбранной цели так же мешает, как и недобор, — поэтому «высокая» тоже красная.
Нет биометрии, цели или ни одного завершённого дня с расходом — подписи нет.

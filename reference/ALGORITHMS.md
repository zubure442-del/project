# Vuelo Ring — алгоритмы обработки данных

Всё, что скрипт считает поверх сырых пакетов. Перенос на другой язык — по этому файлу,
не по коду: код местами исторический.

---

## 1. Фильтр артефактов пульса

Кольцо иногда выдаёт замер, оторванный от соседних на 40–60 ударов: рука сдвинулась,
кольцо провернулось. Такой выброс ломает и график, и расчёт нагрузки.

Замер считается артефактом, если выполнено всё сразу:

- он отличается от последнего «хорошего» замера на `HR_GLITCH_JUMP` = 30 уд/мин и больше;
- следующий за серией замер возвращается к прежнему уровню в пределах
  `HR_GLITCH_RETURN` = 15 уд/мин;
- длина серии — не больше `HR_GLITCH_MAX_RUN` = 2 замеров подряд;
- разрыв по времени внутри проверяемого куска не превышает
  `HR_GLITCH_MAX_GAP` = 2400 с (40 минут).

Последний порог зависит от периода автозамера: при 15–30 минутах хватает 40 минут,
при периоде 60 минут его надо поднять примерно до 4200 с. Разумнее считать его
динамически: медиана интервалов между замерами × 1.5.

Сырой архив пульса не изменяется. Очищенные данные идут в график и в расчёт индекса,
число отфильтрованных замеров показывается пользователю.

## 2. Сон

Минутные состояния из `0x11` собираются в «сессии»: разрыв больше 2 часов начинает
новую сессию. Сессия относится к дате своей **последней** минуты — иначе ночной сон
разрезается полуночью пополам.

Внутри сессии: `состояние >= 80` — глубокий сон, `1..79` — лёгкий, `0` — бодрствование.

## 3. Индекс Vuelo (0–100)

Модель намеренно пессимистичная: она не «успокаивает», а штрафует. Три блока.

**Ресурс (вес 15 %)**

```
объём сна      = min(100, минут_сна / 420 * 100)
качество сна   = 100, если доля глубокого сна в 0.15..0.25
                 иначе max(0, 100 - |0.20 - доля| * 400)
база сна       = объём * 0.7 + качество * 0.3
оценка SpO2    = 100 при среднем >= 95 %, иначе max(0, 100 - (95 - среднее) * 20)
оценка HRV     = min(100, среднее / 65 * 100)
ресурс         = база сна * 0.6 + HRV * 0.2 + SpO2 * 0.2
```

**Активность (вес 70 %)**

```
шаги           = min(100, шаги_за_день / 10000 * 100)
максимальный пульс = 208 - 0.7 * возраст
кардио         = за каждый очищенный замер пульса: >85 % максимума +2.0,
                 70..85 % +1.0, 60..70 % +0.5
нагрузка       = min(100, шаги * 0.7 + кардио * 4)
```

**Метаболизм (вес 15 %)**

```
глюкоза        = 100 при <= 5.2 ммоль/л, иначе max(0, 100 - (глюкоза - 5.2) * 40)
давление       = 100 при < 120/80; 70 при <= 130/85; иначе max(0, 100 - (сист - 130) * 5)
метаболизм     = глюкоза * 0.5 + давление * 0.5
```

**Сборка и штрафы**

```
индекс = ресурс * 0.15 + нагрузка * 0.70 + метаболизм * 0.15
штраф  = 1.0
         - (глюкоза - 6.0) * 0.4, если средняя глюкоза > 6.0
         - 0.2, если сон есть, но меньше 4 часов
индекс = max(0, индекс * штраф)
```

**Известная особенность.** Отсутствующие данные считаются нулём, а не «нет данных».
День без замеров SpO2 занижает индекс так же, как реальная гипоксия. То же с HRV,
глюкозой и давлением — при их отсутствии метаболический блок даёт ровно 0 из 15.
Это осознанный выбор автора для личного скрипта, но для приложения на нескольких
пользователей так нельзя: нужно либо перевзвешивать доступные компоненты, либо
показывать «недостаточно данных». Решение за владельцем продукта.

## 4. Единицы и интервалы

| Величина | Источник | Шаг по времени |
|---|---|---|
| Шаги | `0x10` | 1 мин |
| Сон | `0x11` — но приходит в окне запроса `0x10`, см. PROTOCOL.md раздел 8 | 1 мин (15 одинаковых байт = 15 минут одной фазы) |
| Пульс | `0x16` | 1 мин (две минуты в пакете) |
| Давление, стресс, глюкоза, HRV | `0x55` | один замер на пакет, пакеты раз в 30 мин (период автозамера) |
| SpO2 | `0x40` | редкие одиночные замеры, один на 15-минутный слот |
| Заряд | `0x0B` | только в ответ на запрос |

Глюкоза передаётся умноженной на 10.

## 4a. Оценка «организма»

Среднее доступных оценок: вариабельность ритма, пульс во сне и кислород.
Нужны любые **два входа из трёх**, иначе оценки нет: по одному входу она была бы случайной.
Кислород кольцо пишет редкими одиночными замерами, поэтому его наличие не гарантировано.

## 5. Ноль — это не замер

Для стресса, HRV, давления и глюкозы значение `0` означает «замера не было», а не «ноль».
Официальное приложение усредняет только значения больше нуля, а ноль показывает как «--».
На живом кольце нули приходят лишь в служебном пакете `23:45`, где вся запись нулевая.
То же правило у SpO2: `0` и `255` — не данные.

## 6. Зоны стресса

Как в официальном приложении, четыре зоны: `0–30`, `31–60`, `61–80`, `81–100`.
Названия в интерфейсе нейтральные — «Низкий», «Умеренный», «Повышенный», «Высокий»:
это оценка кольца по пульсовой волне, а не медицинский показатель.
